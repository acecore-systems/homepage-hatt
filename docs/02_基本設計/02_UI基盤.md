# UI基盤（Tailwind CSS v4）

## 目的

公開ページ、ブログ、作品一覧、講座、CMS由来の告知を、Tailwind CSS v4を唯一のCSSコンパイラとして提供する。移行では情報設計、URL、コンテンツ契約、操作方法を変えず、既存の視覚表現を維持する。

## ビルド経路

- AstroのVite設定で`@tailwindcss/vite`を使用する。
- `src/styles/global.css`がTailwindのエントリポイントであり、`@theme`、共通のbase、既存画面を構成するcomponent layerをまとめる。
- UnoCSSとその設定ファイルは使用しない。
- Lucideアイコンは`@iconify/tailwind4`の`icon-[lucide--{name}]`ユーティリティで生成する。CMSの選択肢も同じ記法に統一する。

## トークン

`@theme`には以下を正本として定義する。画面実装では、色は`text-ink-900`や`bg-paper`、角丸は`rounded-hatt`、影は`shadow-hatt`のようにTailwindユーティリティで参照する。

| 種別         | トークン                                                                       |
| ------------ | ------------------------------------------------------------------------------ |
| 色           | `ink-*`, `line`, `paper`, `surface`, `cyan`, `mint`, `ember`, `pollen`, `navy` |
| 書体         | `font-sans`                                                                    |
| 形状         | `radius-hatt`, `shadow-hatt`                                                   |
| レスポンシブ | `hatt-mobile` (680px), `hatt-tablet` (940px)                                   |
| 動き         | `ease-hatt`                                                                    |

既存のセマンティックなコンポーネントクラスは`components` layerに置く。新しい単発の調整はユーティリティを優先し、複数画面で再利用する複合パターンだけをcomponent layerへ追加する。

## Preflightとアクセシビリティ

Preflightは導入しない。サイトには既存のリセットと多数のコンポーネント既定値があり、TailwindのPreflightを重ねると見出し・フォーム・メディアの既定値が変わるためである。代わりにbase layerで、`box-sizing`、画像の縮小、フォント継承、最小表示幅を明示する。

- キーボード操作ではリンク、ボタン、フォーム、`summary`に共通の見えるフォーカスリングを出す。
- `prefers-reduced-motion: reduce`ではスクロール、アニメーション、トランジションを抑制する。
- レスポンシブ確認は少なくともデスクトップ幅、940px以下、680px以下で行う。

## CMS互換

告知データの旧`i-lucide-*`値はビルド時に`icon-[lucide--*]`へ正規化して表示を維持する。新規入力はCMS設定にあるTailwind記法だけを使う。
